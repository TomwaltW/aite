## 一、产品闭环里还缺的（用户在飞书里摸得到）

### 1. 卡片上一个按钮都没有 → **BB5**

lark-oapi-go v3.12.0 在长连接上把非 event 帧**整条丢弃**（`ws/client_message.go:79`），
唯一的 `WithCardHandler` 钩子是注释掉的。契约 R3 的 `stop` / `evidence` 两个动作都还在，
`buildActions`（`edge/internal/feishu/cards.go:151`）也没删，但渲染出来的按钮点了一定没反应，
所以现在改成卡片末尾一行文字提示。

「看证据」当前**只能走 CLI** —— 群里的人根本够不着。这是 P0 闭环里唯一一处
「契约里有、产品里摸不到」的能力。

### 2. `!stop` 省略任务号 + 本群有多个任务 → 回「没有这个任务」 → **BB1**

`plane.rs:783` 的 `(tasks.len() == 1).then(...)`：多于一个就 `None`，
一路走到 `NO_SUCH_TASK_TEXT`。用户刚在 `!status` 里看见三个任务，
敲 `!stop` 被告知「没有这个任务」。W2 记过，AA2 确认**还没销**。

### 3. 乱序重推的话题追问会被丢弃 → **BB1**

追问被平台重推在它的 root 之前时，话题会话还不存在、它自己又没 @，
命中 R8「其余丢弃」，用户那边零回复。飞书通常保序，所以是「乱序时才炸」。

### 4. 丢弃的事件不留痕，counters 没有查看入口 → **BB1**

R1/R2/R8 丢弃时只 `bump("events.dropped")`，**INFO 级别没有日志**；
core 侧 `counters()` 产品代码里零调用方，只有 `!status` 尾巴漏出 `events.dropped` 一个数。
M4 判「没投递 vs 投递了被丢」只能去开放平台翻推送记录。
（edge 侧退出时会打一行 `edge.counters`，core 侧连这个都没有。）

## 二、证据链的成色 → **BB2**

### 5. `created_at` 不进 hash 链

`hash = chain_hash(prev_hash, payload_hash)`，而 `payload_hash` 只覆盖 payload。
**把 `events.jsonl` 里所有时间戳改掉，链校验照样全绿。**
M2/M3 的时序判断全建立在这些时间戳上。

### 6. 卡片的发送与更新不写 evidence，也没有日志

M3 明确要求「卡片至少更新 3 次且不新增消息」，而 `send_card` / `update_card`
在证据里没有任何痕迹 —— 只能肉眼数。

### 7. 三处「记了等于没记」

| 位置 | 病 |
|---|---|
| `checklist_op` 的 check/fail | 只记 `id` + `state`，不带那一项的文本 —— 单看一条读不懂，每个消费方都得自己回放 `add` |
| `tool_result` | 只有 `content_hash`，没有摘要。工具失败时拿不到那一行具体报错，排 M3 沙箱问题时最疼 |
| 沙箱 id | 不进证据。任务和容器对不上号，查「哪个容器该收没收」只能靠时间先后猜 |

## 三、工程面：Linux 上真能跑 → **BB3**

### 8. `make compose-up` 在 Linux 上起不来

target 就一行 `docker compose up -d`：不传 `AITE_UID` / `AITE_GID` / `AITE_DOCKER_GID`，
也不 `mkdir -p data`。AA1 把两个容器降到非 root 之后，Linux 上 core 死在
`建不出目录 data/evidence：Permission denied`，配 `restart: unless-stopped` 就是崩溃循环。
README 现在靠一句「要么按上面那样手敲」兜着 —— 这是文档在替代码打补丁。

### 9. `data/.gitkeep` 那条治本改法没做

入库一个 `data/.gitkeep`，checkout 出来就归当前用户，CI 与本机都不用再 `mkdir -p data`。
AA1 因为 `.gitignore` 不在可写面没做。

### 10. CI 的 Linux 判据，AA1 一条都没有第一手证据

`AITE_DOCKER_GID` 在真 Linux 上的取值没验过；GitHub runner 的 `id -u` / `id -g`
具体是多少没有第一手证据；「换一个真的不同的 uid」（1777 那条设计的全部意义）没实测过；
edge 的 `group_add` 默认值 0 在 Linux 上给容器一个用不上的 root 组。

### 11. edge 镜像没用仓库原文在联网环境建过一次

本机连不上 proxy.golang.org，AA1 用的是注入了 `GOPROXY=file://` 的副本。
**仓库里那份 `docker/edge/Dockerfile` 至今没有一次「用原文建成功」的记录。**

### 15. 台账里有三条归因是错的，AA3 量出了正确答案但没人去改表

「不透明载荷」的真判据是命令替换 `$(…)` / 反引号 / `$((…))`（不是「正文太长」，
