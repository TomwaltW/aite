# 3 分钟演示 · 分镜脚本

对应 `docs/dev-spec-2026-09-09.md` §1 里那句「能录一段 3 分钟演示」。

这份文档回答的问题只有一个：**三分钟里按什么顺序，让一个没看过代码的人看懂这东西凭什么值钱。**

> 和 `docs/acceptance-M.md` 的分工，一句话说清：
>
> | | 验收剧本 | 本文 |
> |---|---|---|
> | 回答 | **对不对** | **凭什么值钱** |
> | 做法 | 穷尽失败面，M1–M6 一条不落 | 砍掉一切枝节，只留四幕 |
> | 读者 | 你自己，对着排查 | 你自己，对着镜头念 |
>
> 两边有重叠的地方（日志关键字、排障动作），本文一律**引它不抄它** ——
> 现场救不回来的，最后都要回到 `acceptance-M.md` 的「不对时查哪」。

---

## 0. 先说三件事

### 0.1 这里的 `python` 一律写成 `.venv/bin/python`

不是洁癖：本机默认 `python3` 是 3.11，满足不了 `requires-python>=3.12`，
而 `python` 这个命令在这台 Mac 上压根不存在。照着敲 `python -m aite.app` 会 command not found。
`docs/acceptance-M.md` 也是这个写法，两份对得上。

### 0.2 「3 分钟」是剪出来的，不是跑出来的

真机上跑完这四幕，实时大约 **4–6 分钟** —— 第二幕一个真模型任务就要 45–90 秒，
第三幕再来一轮。**这是预期，不是故障**。

所以：录的时候不要赶，按 §7 的剪辑规则剪到 3 分钟。
§4 每一幕标的时间是**成片时长**，不是你在现场要掐的秒表。

如果是**当着人实时演**（不录像），那就把 §4 里每一幕的「说什么」当成填等待时间的稿子 ——
它们的长度就是照着等待时间写的。

### 0.3 全片唯一的卖点：那张卡在原地变

演砸的定义不是「出错了」，是「观众没注意到那张卡片一直是同一条消息」。

群里的机器人观众见得多了，它们的共同点是**刷屏**：干一步发一条，十步十条。
Claude Tag 不一样的地方就在这儿 —— 一张卡片，从头到尾就那一条消息，内容在里面改。
第二幕如果观众只看见「哦它画了张图」，没看见「消息没有变多，只是那张卡在变」，
这三分钟就白演了。

第二幕的旁白里有一句加粗的，那句必须说到。

## 1. 演示前 5 分钟：检查清单

**按顺序做，别跳、别换序** —— 第 ⑤ 步（热身）会留下垃圾，第 ⑥ 步专门收拾它；
换个顺序就白热身或者白收拾。①–④ 任一不过，就别往下走。

要三个终端窗口，先在仓库根目录开好：

| | 干什么 | 入镜？ |
|---|---|---|
| **A** | 跑常驻进程（`aite.app`） | 入镜，右下小窗 |
| **B** | 容器面板 | 入镜，右上小窗 |
| **C** | 敲命令（热身、清理、第四幕） | 只有第四幕入镜，全屏 |

A 窗口里跑着前台进程，**在那儿敲不了字** —— 这就是为什么要第三个窗口。

---

**① 起飞前自检 —— 不带 `--offline`**（C 窗口）

```bash
.venv/bin/python scripts/preflight.py            # 七组全跑，FAIL 必须是 0
```

第 ④ 组（飞书身份对得上）尤其要过：**配错了应用，第一幕会完全静默**，
没有任何报错 —— 镜头前最难堪的一种死法。

**② `config/aite.yaml` 里的单价填了**

```yaml
model:
  price_in_per_mtok: <填>      # 元/百万 token
  price_out_per_mtok: <填>
```

不填，卡片 footer 的「¥0.00」和第四幕证据里的「花费 ¥0.0000」全是 0。
第二幕和第四幕最有说服力的一栏就废了 —— 「它花了几分钱办完这件事」是这场演示的暗线。

（改完要在 ⑤ 之前改，因为配置是起飞那一刻读进去的。）

**③ 沙箱镜像在**（C 窗口）

```bash
docker images aite-sandbox:p0                    # 有一行
# 没有就：docker build -t aite-sandbox:p0 docker/sandbox   —— 几分钟，别临场做
```

**④ 生成素材**（C 窗口）

```bash
.venv/bin/python scripts/demo_fixture.py all
# → /tmp/aite-demo/sales.csv     第二幕的附件，也是 ⑤ 热身要用的那份
# → /tmp/aite-demo/history.txt   垫场文本，⑦ 要用
```

把它打印出来的这两行**抄在手边**，第二幕要拿它当场核对模型：

```
  最高   2025-11  140,494 元
  最低   2025-07  60,700 元
```

（同样参数跑两次字节一致，所以彩排看到的图和正式演示那张是同一张。）

**⑤ 起飞 + 完整热身一遍**

A 窗口起飞：

```bash
.venv/bin/python -m aite.app --config config/aite.yaml
```

然后把**第二幕原样跑一次**（拖 `sales.csv` 进群、发那句话、等到卡片变绿）。
这一遍吃掉三种「第一次」成本：镜像首次拉起、模型端点首次握手、飞书 API 首次鉴权。
也顺带验了模型今天出牌正不正常 —— **第二幕最致命的那种翻车（模型一步就 `final`、
卡片压根没出现），只有热身能提前发现**。

热身完在 A 窗口 Ctrl-C 停掉进程。

**⑥ 收拾热身留下的三样东西**（C 窗口）

```bash
# 1. 群里：把热身发的消息和卡片删掉
# 2. 本地状态
rm -rf data/aite.db data/evidence data/artifacts
# 3. 热身留下的容器 —— 不删的话第一幕开场时面板里就已经有一行了
docker rm -f $(docker ps -aq --filter label=aite.task)
```

第 3 条为什么重要：沙箱是 `reap_idle` 收的，空闲 **300 秒**才收，而且进程停了就没人收。
热身留下的容器会一直躺在面板里 —— 于是**第一幕「面板保持空」和第二幕「凭空冒出一个容器」
这两个信号同时失效**，而这两个是全片唯二的现场证据。

> ⚠️ 这条会删掉**所有**带 `aite.task` 标签的容器。别在正跑着 `pytest tests/sandbox`
> 的机器上敲它。演示机上没这个问题。

清 `data/` 的理由：`task_no` 从 `#A1` 重新开始，卡片抬头干净（`#A1` / `#A2` / `#A3`
一路数下去，观众看得出这是第几件事）；第四幕 `--list` 里只有今天这三个任务，
不用在一堆旧任务里翻。

代价：会话历史没了，所以 **M6（重启续接）演不了** —— 反正也不演（§6）。

**⑦ 群里垫历史**

按 `history.txt` 里的说明，把 8 条消息发进测试群。**一条都不要 @Aite** ——
@ 一下就是一个任务，群里会瞬间多出一堆卡片。

即使不演加演那段（§5），这一步也要做：**空群看着假**。
观众第一眼看到的是一个有人说话的群，不是一个只有你和机器人的空房间。

**⑧ B 窗口开容器面板**

```bash
# macOS 没有 watch，用这个循环。开场时它应该是空的（⑥ 已经清过）
while true; do printf '\033[H\033[2J'; date +%H:%M:%S; \
  docker ps --filter label=aite.task \
    --format 'table {{.ID}}\t{{.Status}}\t{{.Label "aite.task"}}'; sleep 1; done
```

**⑨ C 窗口里把第四幕的两个函数定义好**（此刻不入镜，第四幕才切过来）

```bash
# 确认 C 窗口的当前目录就是仓库根目录 —— ev 里的 config/aite.yaml 是相对路径
ev()   { .venv/bin/python scripts/evidence_show.py --config config/aite.yaml "$@"; }
last() { ev --list --json | .venv/bin/python -c 'import json,sys;print(json.load(sys.stdin)["tasks"][0]["task_id"])'; }
```

第四幕要敲的就是 `ev --list` 和 `ev $(last)` 两行。
不这么准备的话，你得在镜头前用鼠标选中一个 36 位 UUID 再粘贴 —— 那 10 秒很难看。

**⑩ A 窗口重新起飞**

```bash
.venv/bin/python -m aite.app --config config/aite.yaml
```

**把 `aite.up` 那一行留在屏幕上**（它写着接了谁：platform / model / sandbox / sqlite / evidence）。
开场第一秒扫过它，是这场演示唯一一次「让人看见接线」的机会。

**⑪ 收拾桌面**：勿扰模式、关掉通知、飞书字号调大、无关的群和窗口全关。

**⑫ 开录前最后一件事：从现在起别再 @ 它。** 任务号是租户内递增的，
开录前多 @ 一次，第二幕卡片抬头就不是 `#A2`、第三幕不是 `#A3` 了 ——
不影响功能，但「编号在涨、这是第几件事」这条线索就断了。

## 2. 屏幕怎么摆

前三幕**分屏，全程不切换**；第四幕切一次到全屏的 C 窗口；收尾切回来。
一共两次切换，都落在幕与幕之间，不打断任何一个正在变的画面。

```
第一 ~ 三幕                                第四幕
┌────────────────────┬──────────────┐     ┌──────────────────────────────┐
│                    │ B 容器面板    │     │                              │
│   飞书群窗口         │ (docker ps)  │     │   C 命令窗（全屏）             │
│   （话题展开）        ├──────────────┤     │     ev --list                │
│                    │ A 进程日志    │     │     ev $(last)               │
│      ~65%          │  (aite.app)  │     │                              │
└────────────────────┴──────────────┘     └──────────────────────────────┘
        C 窗口此时不在画面里 ↑                    A / B 此时不在画面里
```

**关于进程日志那个窗格，先说清楚一件事：正常跑通时它是安静的。**

happy path 上全仓只有两条 INFO 会出现：起飞那条 `aite.up`，和 reaper 收容器时的
`control.reaped`（空闲 300 秒才收，三分钟里不会出现）。另外两条 `aite.stopping` /
`aite.down` 要 Ctrl-C 才打，演示期间见不到。飞书 SDK 自己的 `Lark` logger
默认也在 WARNING（本机 import 看过）。剩下的关键字——`ingress.slow_callback`、
`worker.model_failed`、`control.reap_failed`——**全都是出事才打的**。

所以别指望「日志在滚」当证据。**证明它没作弊的是另外两样**：

1. **现场**：容器面板里凭空冒出来的那个容器（第二幕）、和第二个容器（第三幕）。
2. **事后**：第四幕的证据链。

日志窗格留着是为了**翻车时第一时间看得见**（红色的 ERROR 一眼就跳出来），
不是为了给观众看。它安静，就是一切正常。

## 3. 分镜总表

| 时间 | 演什么 | 观众看见的信号 | 最可能翻车的点 |
|---|---|---|---|
| 0:00–0:15 | 开场：这是什么 | 一个有人说话的群 + `aite.up` 那行 | 群里是空的 → 假 |
| 0:15–0:45 | **第一幕** @ 一下就有人应（M1） | 2 秒内 👀；随后一条**纯文本**回复；容器面板保持空 | 完全静默（应用配错，preflight ④ 该拦住） |
| 0:45–1:45 | **第二幕** 把 CSV 画成图（M3）· 主戏 | 一张卡片**原地**变 ≥3 次；容器冒出来；PNG 回到话题；卡片变绿 | 模型一步就 `final`，卡片压根没出现 |
| 1:45–2:15 | **第三幕** 话题里追问（M4） | 新卡片 `#A3`；**没有再传一次 CSV**；容器变成 2 个；第二张图回同一话题 | 上一幕还没变绿就追问 → 被并成 steer，不新建任务 |
| 2:15–2:40 | **第四幕** 证据链 | 一条时间线，末尾 `hash 链 OK`；花费不是 0 | 单价没填 → 花费全是 ¥0.0000 |
| 2:40–3:00 | 收尾：P0 验掉了什么 | 话题里：绿卡片 + 两张 PNG + 文本 | 顺嘴讲还没做的东西 |

## 4. 逐幕

### 4.1 开场 · 0:00–0:15

**屏幕怎么摆** — 分屏。飞书那半是测试群的群视图（不是话题），能看到刚垫的那几条消息。
右上容器面板空，右下 `aite.up` 那行停在那儿。

**手上做什么** — 不动。就让画面停 3 秒。

**几秒内该出现什么** — 什么都不用出现。这 15 秒是给观众建立「这是一个真的、有人在用的群」。

**同时终端在滚什么** — 什么都不滚（§2 已经解释过了）。开场镜头扫一眼 `aite.up` 那行就够。

**说什么** — 一句话，别超过三句：

> 「这是 Aite。在飞书群里 @ 它，它接活、干活、把结果发回同一条话题里。
> 它不是一个问答机器人 —— 它会写代码、在隔离沙箱里跑、把文件发回来，
> 而且每一步都留下可校验的证据。」

**这里必须说到**：「同一条话题里」。后面三幕全靠这个词串起来。

**不要说**：架构、契约、P0/P1、模块名。一个都不要。

**翻车怎么救** — 这一幕唯一的翻车是群里没垫消息（回到 §1 ⑦）。开录前扫一眼就行。

---

### 4.2 第一幕 · @ 一下就有人应（M1）· 0:15–0:45

对应 §2.4 M1。这一幕的任务是**建立节奏**：证明它在听，而且答得快。

**屏幕怎么摆** — 分屏不动。飞书那半保持群视图。

**手上做什么** — 群里发一条，**逐字**：

```
@Aite 你好，你能干什么？
```

**几秒内该出现什么**

| 时间 | 信号 |
|---|---|
| ≤2 秒 | **你那条消息**上出现 👀（不是它新发一条）。这是 `add_reaction(ack)`，先于任何回复 |
| 3–15 秒 | 话题里一条**纯文本**回复。**没有卡片** |
| 全程 | 容器面板**保持空** |

**同时终端在滚什么** — 什么都不滚。**容器面板保持空，本身就是这一幕的信号之一**：
简单问答不开沙箱。

**说什么** — 两个点，都必须说到：

> 「注意这个 👀 —— 它是**两秒内**贴上来的，跟它想多久没关系。这是『收到了，我在办』。」
>
> 「回过来的是一条**纯文本**，没有卡片。一步能答完的事，它不给你摆流程。
> 右边的容器面板是空的 —— 这种活它不开沙箱。」

**翻车怎么救**

| 症状 | 镜头前怎么办 |
|---|---|
| 👀 慢了（3–5 秒） | **不停**。旁白盖过去，别道歉，别看表 |
| 回复很长很啰嗦 | **不停**。别等它说完，直接进第二幕 |
| 有 👀，没回复 | **停**。模型这一步炸了（日志会有 `worker.model_failed`）。回 `acceptance-M.md` M1 那张表 |
| 完全静默：没 👀、没回复 | **停，重录**。八成是 `FEISHU_BOT_OPEN_ID` 配的不是这个应用 —— §1 ① 该拦住的。**别在镜头前修** |

---

### 4.3 第二幕 · 把 CSV 画成图（M3）· 0:45–1:45 —— 主戏

对应 §2.4 M3。全片 60 秒的一半在这里，卖点也全在这里。

**屏幕怎么摆** — 分屏不动，但**飞书那半要滚到能完整看见那条话题**：
你的 @ 消息在最上面，下面留出足够空间让卡片出现。
卡片一出现就**不要再滚动、不要再点任何东西** —— 观众要能看出「画面里消息的条数没变」。

**手上做什么** — 把 `/tmp/aite-demo/sales.csv` 拖进输入框，**和文字同一条消息**发出去，逐字：

```
@Aite 把这个 CSV 画成月度趋势图，标出最高和最低的月份，最后用一句话说结论
```

> 这句话里的三个动作（画图 / 标最值 / 给结论）是**故意的**：
> 它们让模型建出至少 3 项 checklist，卡片才会更新 ≥3 次。
> 只说「画成月度趋势图」，模型很可能两步就干完，卡片只变一次 —— 主戏就没了。

**几秒内该出现什么**

| 时间 | 信号 |
|---|---|
| ≤2 秒 | 你那条消息上 👀 |
| 5–20 秒 | **卡片出现**：蓝色抬头 `#A2 把这个 CSV 画成月度趋势图…`；下面三格「发起人 / 开始于 / 状态：进行中」；再下面几行 ⬜ 待办；底部 note 一行 `已用 N 步 · ¥X.XX`；一个红色「停止」按钮 |
| 之后每十几秒 | 卡片**原地**变：⬜ 逐个翻成 ✅，footer 的步数和金额在涨。**消息条数不变** |
| 它下载附件那一步 | 容器面板里**冒出一个容器**，`aite.task` 那列就是这个任务的 id |
| 收尾三连（顺序固定） | ① 一个 `.png` 文件消息 → ② 一条文本回复 → ③ **卡片抬头由蓝变绿，状态变「已交付」** |

最后那个绿，是这一幕的落点。等它变完再说收尾那句。

两个别被绊到的细节：

* **待办项只有 ⬜ 和 ✅ 两种状态**（失败是 ❌）。契约里还有个「进行中 🔄」，
  但 P0 的 worker 从不设它 —— 别盯着等一个不会出现的图标。
* **容器是在「下载附件」那一步就起来的**，不是等到跑代码。`download_attachment`
  要把文件写进沙箱的 `/work/in/`，所以沙箱那时就有了。比你预期的早十几秒。
* PNG 的文件名就是模型写在 `/work/` 下的那个名字（`out.png`、`trend.png`……都可能），
  别把某个具体文件名写进台词。

**同时终端在滚什么** — 日志窗格安静。**要看的是容器面板**：
从空 → 冒出一行 → 一直在（`reap_idle` 是 300 秒空闲才收，三分钟内不会消失）。

**说什么** — 四句，第一句最重要：

> **「看清楚：群里没有多出第二条卡片。从头到尾就那一张，它在原地改自己。
> 一般的群机器人干一步发一条、十步刷十条 —— 这个不刷屏。」**
>
> 「右边这个容器是它现在的工作台。**没有网络**，跑完就回收。
> 里面跑的代码是它自己写的，不是我预先塞进去的。」
>
> 「图回到了**同一条话题**里，不是甩到群里。这个群里同时有五件事在办也不会串。」
>
> （对着手边抄的那两行）「它说最高是 2025 年 11 月、最低是 2025 年 7 月 —— 对得上。
> 它不许说自己没做过的事，这是写死在系统提示里的。」

**这里必须说到**：第一句（原地更新，不刷屏）。其余三句时间不够可以砍。

**翻车怎么救**

| 症状 | 镜头前怎么办 |
|---|---|
| **没出卡片，直接回了一段文字** | 全片最致命的一种。模型一步就 `final` 了（W3 的 Answering 路径，**不是 bug**）。现场救：在同一条话题里追一句「分步做：先读数据，再画图，最后给结论」—— 卡片就出来了，只是多花 20 秒。**彩排必须验到这条不发生**；两次彩排都发生，就把那句话的动作数从 3 个加到 4 个 |
| 卡片出来了，但只更新 1–2 次 | 观众看不出「在变」。旁白临时补一句：指着 footer「步数和花费在涨，这张卡一直在写自己」。事后照上一行改台词 |

| PNG 里中文是方框 | 用错镜像了（不是 `aite-sandbox:p0`）。**停，重录**，回 §1 ③ |
| 回帖里有「产物 … 未找到」 | 模型给的路径不在 `/work` 下。不停，任务仍然 delivered，但这一幕的落点弱了一半 —— 录像的话建议重来一条 |
| **同一个任务出现了两张卡片** | **停，这是 bug**，不是环境问题。记下两条卡片的 message_id 和 `ev $(last)` 的输出交给开发 |
| 容器面板一直是空的 | 它既没下载附件也没跑代码（多半是直接编了个答案）。**停** —— 这一幕的可信度全在那个容器上 |

> 更细的排查（`--only tool_call,tool_result` 怎么读、`FAIL[sandbox]` / `FAIL[timeout]` 分别意味着什么）
> 在 `docs/acceptance-M.md` 的 M3「不对时查哪」。镜头前不查，录完再查。

### 4.5 第四幕 · 刚才那一分钟它到底做了什么 · 2:15–2:40

**手上做什么** — 两行，就两行（函数在 §1 ⑨ 已经定义好）：

**几秒内该出现什么**

`ev --list` —— 三行，就是今天这三个任务（§1 ⑥ 清过 `data/`），最近的在最上面。

**同时终端在滚什么** — 这一幕终端就是主角。

**说什么** — 两句：

> 「刚才那一分钟它到底做了什么，这里一条不落：哪一步问了模型、哪一步跑了代码、
> 跑了多久、产出文件的 sha256 是多少、**一共花了一分几厘钱**。」
>
> 「最后这行 `hash 链 OK`：每条事件都咬着上一条的哈希。
> 中间抽掉一条、改掉一个字，这里就会红，并且告诉你断在第几行。
> 这不是日志 —— 日志可以改。」

**这里必须说到**：花费那个数字，和 `hash 链 OK`。这两样是这一幕存在的全部理由。

**翻车怎么救**

| 症状 | 镜头前怎么办 |
|---|---|
| 花费全是 `¥0.0000` | §1 ② 没做（单价没填）。**这一幕最有说服力的一栏废了**。旁白临时改口，只讲 hash 链；录像的话补完单价重录这一幕（证据是落盘的，`--config` 一带就重算） |

> 「它读的是这个群真实的聊天记录。注意它**没有**提运维那条『告警已经处理完了』，

## 6. 不演什么，以及为什么

写在这儿，免得下次有人问「怎么没演断网」，也免得临场心软加戏。

| 不演 | 为什么 |
|---|---|
| **M2 · 拔网线 30 秒再插回** | 镜头前拍不好看：30 秒里画面上什么都不发生，只有一行 `feishu.reconnecting` 在退避（1s→2s→…→30s）。而且它的成败取决于飞书补不补推——**平台不保证补推**，`acceptance-M.md` M2 明写着连续两次不补推就算平台行为。演示不押注在别人的行为上。留给验收 |
| **M6 · 重启后旧线程续接** | 同样是「什么都不发生」的 30 秒：杀进程、确认没了、重新起飞、等长连接接上。而且 §1 ⑥ 清空了 `data/`，会话历史本来就没了。留给验收 |
| **§3.7(a) 的实验（话题里不带 @）** | 第三幕已经说明理由：赌赢了只证明一件观众不关心的事，赌输了是 30 秒死画面。留给验收（`acceptance-M.md` M4 写了怎么判「没投递」还是「投递了被丢」） |
| **`!status` / `!stop` / `!restart` / `!new`** | 有用，但它们是**操作员**的功能，不是让人看懂这东西凭什么值钱的东西。观众此刻还不是操作员 |
| **卡片上的「停止」按钮** | 同上。而且卡片上**没有**「证据」按钮（`render_card` 用的是 `actions` 的默认值 `["stop"]`），第四幕的证据是在终端里拿的 —— 现场别去点卡片找证据，找不到 |
| **故意篡改证据、演示 hash 链变红** | 很有说服力，但要多花 40 秒，而且要在镜头前 `vi` 一个 jsonl 文件，画面很技术、很啰嗦。第四幕那句「改掉一个字这里就会红」讲到就够了。真被追问，当场演给他看（`acceptance-M.md` §0.3 有命令） |

## 7. 剪辑规则：哪一段能加速，哪一段一帧都不能剪

§0.2 说过实时要 4–6 分钟。压到 3 分钟只能靠加速，不能靠跳切。

**一帧都不能剪 / 不能跳的**：

1. **第二幕从卡片出现到卡片变绿的整段**。这是全片的证据：观众要能看出
   那张卡自始至终是同一条消息。中间跳一刀，「消息没有变多」就无从判断了。
   要压时长就**整段等速加速**（2×，右下角打个 `×2` 角标），画面必须连续。
2. **每一次 👀 出现的那一两秒**。它是「2 秒内响应」这个说法的唯一凭据，
   加速过的 👀 说明不了任何事。
3. **第二幕、第三幕的收尾三连**（文件 → 文本 → 卡片变绿）。顺序本身是内容。

**可以放心加速或剪掉的**：

- 模型在想、卡片没变的那些空档 → 2× 加速，或直接剪（但要剪在**卡片没在变**的时刻）
- 第一幕那条回复正文很长时，中间滚动的部分
- 第四幕命令敲下去到输出打完之间
- 幕与幕之间你切窗口、滚页面的动作

**字幕**：第二幕那句加粗的旁白建议上字幕。它是全片唯一一句「说了才有用」的话，
观众走神就没了。

## 8. 什么情况必须停下重录

不要救的，一律停。镜头前修东西比重录贵得多。

| 情况 | 为什么不救 |
|---|---|
| 第一幕完全静默（没 👀、没回复） | 配置层面的问题（八成是 `FEISHU_BOT_OPEN_ID`）。现场改配置要重启进程，重启就得重来 |
| **同一个任务**出现了两张卡片 | 这是 bug，全片的卖点当场被推翻。**停下来记录，别继续演**（第二幕和第三幕各有一张，那是对的；说的是同一个 `#A` 号出现两张） |
| PNG 里中文是方框 | 镜像不对。重 build 要几分钟 |
| 容器面板全程是空的 | 说明它没真跑代码。这场演示的可信度归零 |
| `hash 链` 红了 | 证据不可信。这一幕不能演，而且要先查清楚为什么 |
| 图回到了群里而不是话题里 | W5 的 bug，第三幕的台词直接不成立 |
| 任何一幕出现 `failed` 状态的卡片（红色抬头） | 观众记住的会是那个红色 |

**记录格式**（停下之后照这个记，比事后回忆有用得多）：

```
哪一幕、第几次录、当时群里发的原话、
ev --list 的输出、ev <task_id> 的输出、日志窗格最后 20 行
```

## 9. 需要总管决定的

| # | 要定什么 | 我的建议 |
|---|---|---|
| 1 | **真模型还是脚本化替身？** | **真模型**。这场演示的全部价值就是「它真的能做」，用替身等于把演示变成一段动画 —— 而且一旦被问到「刚才那是真的吗」，全片作废。`--model live` 已经被 T12 修好并实跑过。代价：第二幕耗时不可控（§0.2、§7 已经给了对策） |
| 2 | **垫场那 8 条历史谁来发？** | 有替身账号就分开发（汇总里出现不同名字，效果好得多）；只有一个账号，全用自己发也成立 —— 拉历史只过滤非真人消息，不看是谁 |
| 3 | **加演那段（M5）演不演？** | 默认不演（§5 给了理由）。如果这次的观众特别在意「它能不能读群里的上下文」，就加，成片按 3:25 算 |
